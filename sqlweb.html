1 Store Procedure

Stored Procedure: El store procedure es un procedimiento o consulta con un nombre, con la que la podes llamar dentro del codigo sin tener que volverla a escribir 

CREAR UNO:
CREATE PROCEDURE ObtenerUsuarios
AS
BEGIN
    SELECT * FROM Usuarios;
END
----------------------------
PARA LLAMARLO:
EXEC ObtenerUsuarios;

2 SQL

Create sirve para crear cosas nuevas dentro de la base de datos 
CREATE TABLE usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY NOT NULL,
    nombre VARCHAR(100),
    email VARCHAR(100)
);

PK (Primary Key): Es como el DNI de cada fila, sirve para identificar de manera única a cada registro.
FK (Foreign Key): Sirve para relacionar una tabla con otra. 
CREATE TABLE pedidos (
    id_pedido INT AUTO_INCREMENT PRIMARY KEY NOT NULL,
    id_usuario INT,
    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario)
);
Insertar Registros

Sirve para meter/agregar datos dentro de una tabla. 
INSERT INTO alumnos (nombre, edad)
VALUES ("Juan", 14);
Iniciar Consultas

Mostras lo que queres ver/seleccionar en la consulta. 
SELECT nombre, email FROM usuarios;

Decis de que tabla estas sacando los datos 
SELECT * FROM usuarios;

sirve para poner una condición, es decir: “Mostrame solamente los que cumplen con esto.” 
SELECT * FROM alumnos WHERE edad > 10;
Filtros dentro de las consultas

Calcula el promedio. 
SELECT AVG(edad) FROM alumnos;

Suma todos los valores. 
SELECT SUM(edad) FROM alumnos;

Cuenta la cantidad de filas de un resultado. 
SELECT COUNT(*) FROM alumnos;

busca el valor más grande. 
SSELECT MAX(edad) FROM alumnos;

busca el valor más chico. 
SELECT MIN(edad) FROM alumnos;

Sirve para ordenar los resultados. Lo podes hacer de forma ascendente (ASC) o descendente (DESC). 
SELECT nombre, edad FROM alumnos ORDER BY edad asc;

Sirve para limitar la cantidad de resultados que devuelve. 
SELECT * FROM alumnos LIMIT 3;

Sirve para buscar textos que coincidan con un patrón. 
SELECT * FROM alumnos WHERE nombre LIKE "J"; --Va a mostrar todos los nombres que empiezen por "J"
Consultas Avanzadas

Sirve para agrupar datos que tienen algo en común. Se suele usar con funciones de agregacion (count, sum, avg) 
SELECT id_usuario, SUM(total) FROM pedidos
GROUP BY id_usuario;

Sirve para filtrar los grupos que creó GROUP BY. 
SELECT id_usuario, COUNT(*) AS cantidad
FROM pedidos
GROUP BY id_usuario
HAVING COUNT(*) > 5;

Una subconsulta es una consulta dentro de otra consulta. 
SELECT nombre, nota FROM alumnos
WHERE nota > (
    SELECT AVG(nota)
    FROM alumnos
); --Calcula el promedio y lo usa para comparar con la nota
-- Si queremos que nos devuelva mas valores en vez de > ponemos IN
La subconsulta ademas de usarla en el where se puede usar en el select y el from

INNER JOIN
Devuelve solo las filas que tienen coincidencia en ambas tablas. 
SELECT usuarios.nombre, pedidos.total
FROM usuarios
INNER JOIN pedidos ON usuarios.id_usuario = pedidos.id_usuario;
JOIN
Es lo mismo que INNER JOIN
LEFT JOIN
Agarra todas las filas de la tabla izquierda, tengan o no coincidencia en la derecha. 
SELECT usuarios.nombre, pedidos.total
FROM usuarios
LEFT JOIN pedidos ON usuarios.id_usario = pedidos.id_usuario;
RIGHT JOIN
Agarra todas las filas de la tabla derecha, tengan o no coincidencia en la izquierda. 
SELECT usuarios.nombre, pedidos.total
FROM usuarios
RIGHT JOIN pedidos ON usuarios.id_usario = pedidos.id_usuario;
OUTER JOIN
Término general para los joins que incluyen filas sin coincidencia (LEFT, RIGHT o FULL). MySQL no tiene la palabra OUTER JOIN sola: se usa combinada con LEFT/RIGHT/FULL.

FULL JOIN
Combina LEFT y RIGHT JOIN: Trae todas las filas de ambas tablas, tengan o no coincidencia. MySQL no lo soporta de forma nativa, se simula con UNION. 
SELECT usuarios.nombre, pedidos.total FROM usuarios 
  LEFT JOIN pedidos ON usuarios.id_usuario = pedidos.id_usuario
UNION
SELECT usuarios.nombre, pedidos.total FROM usuarios RIGHT JOIN pedidos ON usuarios.id_usuario = pedidos.id_usuario;
CROSS JOIN
Devuelve el producto cartesiano: cada fila de una tabla combinada con cada fila de la otra (sin condición ON). 
SELECT usuarios.nombre, categorias.nombre
FROM usuarios
CROSS JOIN categorias;
Eliminar y Actualizar Datos

Borra lo que vos pidas completamente. 
DROP TABLE usuarios;

Borra las filas/columnas de una tabla según una condición. 
DELETE FROM usuarios WHERE id = 5;

Sirve para vaciar una tabla completa. 
TRUNCATE TABLE pedidos;

Sirve para modificar la estructura de una tabla que ya existe. 
ALTER TABLE usuarios ADD COLUMN telefono VARCHAR(20);

5 Normalización

La normalización es una forma de organizar las tablas de una base de datos para evitar: repetir información innecesariamente; datos contradictorios; problemas cuando agregás, modificás o borrás información.

Cada celda debe tener un solo valor.

Los datos tienen que depender de toda la clave primaria, no solamente de una parte.

Un dato no debería depender de otro dato que no sea la clave.

6 DER (Diagrama Entidad-Relación)

El DER es un dibujo que muestra cómo está organizada una base de datos y cómo se relacionan sus tablas.

Una entidad es una cosa o elemento sobre el que queremos guardar información en nuestra base de datos.

Y los atributos son las características o datos que describen a una entidad.
